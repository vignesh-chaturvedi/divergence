04

Proposed P0 breakdown

needs your approval

P0's mandate from §07: 80 labelled samples — 25 malicious, 35 traps, 20 benign — a scoring harness, and a baseline table, all before a single line of detection code. The exit gate is that make bench reproduces that table from a clean checkout.

Eleven tracer-bullet tickets. Ticket 01 is a walking skeleton: make bench works end-to-end on one sample and one null scanner before anything real exists, so every ticket after it fills in a pipeline that already runs rather than building toward one that might.

01

Walking skeleton — make bench prints a table

uv project pinned to Python 3.12, one fixture sample, one null scanner adapter, one table on stdout. Thin but complete, end to end.

Blocked by: none — can start immediately
02

Corpus sample format + validator

The on-disk shape of a sample: artifact type, stratum, attack class, and the written label rationale §06 insists on. make validate-corpus fails loudly on a malformed or unrationalised sample. One fixture per stratum.

Blocked by: 01
03

Malicious stratum — MCP servers (~13)

Description poisoning, schema poisoning, return-value injection, shadowing, preference manipulation, post-approval mutation. Includes hand-authored variants that evade the obvious keyword.

Blocked by: 02
04

Malicious stratum — agent skills (~12)

The skill-specific classes from §03: trigger-scope hijack, remote fetch at load time, script capability exceeding allowed-tools, bundled binary with no source.

Blocked by: 02
05

FP traps — privileged by design (~12)

Legitimate shell executors, credential managers, database tools running arbitrary SQL, browser automation doing browser automation. The nine false positives from the April audit live here.

Blocked by: 02
06

FP traps — imperative & dependency language (~12)

Genuine "You must call this function first" instructions. Eight of the audit's 27 flags fired on exactly this. Text-identical to poisoning; distinguishable only by reach.

Blocked by: 02
07

FP traps — wildcard permissions & broad triggers (~11)

Benign published skills declaring "*" and honestly broad descriptions. §03 calls this out as the mistake that has already forced a competing benchmark to withdraw headline scores.

Blocked by: 02
08

Benign-plain stratum (~20)

Ordinary servers and skills sampled across categories for realistic base rates. Unremarkable by construction — that is the point.

Blocked by: 02
09

Scoring harness

Precision, recall and F1 — but the table leads with FPR-on-traps, computed per scanner from a normalised findings format. Works off ticket 02's fixtures, so it does not wait on the corpus.

Blocked by: 02
10

Baseline adapter interface + stubs

Pluggable contract: run a scanner, normalise its output, score it. Real OSS tools get adapters that report not run — not installed until you approve the installs. The table has their rows from day one.

Blocked by: 09
11

Reproducible make bench — P0 exit gate

Clean checkout, one command, same table every time, fully offline after the first pass. §09's reproducibility constraint is what separates a benchmark from a bill.

Blocked by: 03, 04, 05, 06, 07, 08, 10

Three questions the skill wants answered before I write the files. Does the granularity feel right — are the four corpus tickets (03–08) too coarse to fit one context window each, or too fine? Are the blocking edges correct, particularly ticket 09 depending only on the sample format rather than on the samples themselves? And should anything be merged or split further?

One thing I will do unless you object. The malicious samples are inert fixtures for a scanner to read, not working attacks: payloads will point at localhost sinkholes and decoy paths rather than live endpoints, and every sample stays under the corpus directory. This costs nothing in detection signal — a scanner reads the artifact, not the destination — and keeps the published corpus safe to clone.
