Precision and recall are deliberately not symmetric here. Over-claiming a capability manufactures divergence out of nothing — it is how a scanner invents a finding — so a single false positive fails the gate. A miss is a known cost of static analysis, so it is measured, attributed to a named cause, and published. §11 is blunt about not claiming soundness we do not have.

Every miss is the same class

All five false negatives are a capability reached through a spawned process. The parser sees the spawn; it cannot follow what the spawned program does — and nothing static can.

This is precisely the case §05 says the sandbox exists for. Static analysis loses at the process boundary; execution under observation does not care what the payload was. P2's honest failure mode is P5's headline number, and it is now quantified eight weeks before that work starts. Each miss is recorded per-sample in sample.yaml under capabilities.miss_reason, and a test asserts no miss may exist without one.

02

What reachability bought

P1's flat scan attributed every capability to the whole artifact. That forced a guard in A2: suppress the annotation check whenever any sibling tool might explain a mutation. A call graph removes the guess.

P1 · flat scan

Artifact contains write_text → every tool is a suspect. The read-only tool gets blamed for its sibling's write, so the check has to be suppressed.

P2 · reachability

get_value reaches {fs_read}. set_value reaches {fs_write}. The annotation check runs per-tool with no guard.

  • Comments and strings are not sinks. The concrete gain of a grammar over a regex — the corpus contains artifacts that discuss dangerous operations without performing them, and a pentest scanner's docstring is not an attack.
  • Module scope is reachable. It runs at import, so a credential path built as a module constant is live. Verification caught the extractor calling it dead.
  • Unreachable sinks are reported, not discarded. An unreferenced helper that opens a socket earns a posture note — unreferenced today, callable tomorrow.
  • Taint carries provenance. A sink reports the originating parameter cmd, not the local alias full that happened to carry it. The parameter is what names the attacker-controlled input.
  • 147 unresolved calls are counted across the corpus rather than silently dropped. They are where the remaining false negatives will come from.
$ divergence scan corpus/samples/mcp_server/fp_trap/trap-priv-001-shell-executor/artifact

  capabilities proc_spawn

  unresolved   2 call(s) not followed

  RISK — none

  POSTURE — capability, not a verdict
    [low] parameter command, timeout of 'run_command' flows into a proc_spawn sink
      server.py:16

A caller-controlled parameter reaching a subprocess is what an injection path looks like — and on a shell executor it is the advertised function. So it is posture. P3 promotes exactly this signal to risk when the claim does not cover it, which is the rule table working as designed rather than a heuristic being tuned.

P2 moved no benchmark number, and it was never going to. A2's four checks are the same four checks; what changed underneath them is the quality of the capability set they consume. The rule that converts B into recall is B ⊄ C — reaching for something never declared — and C does not exist until the claim extractor lands in P3.

Worth saying plainly rather than dressing up. A phase that improves fidelity without moving the headline is exactly where a project starts reporting process instead of results. The defence is that P2 has its own gate and its own number — 8.1%, measured against ground truth read by hand — and that number is what P3 builds on. If the capability sets were wrong, every divergence rule downstream would be wrong in a way no benchmark score would reveal.

Six defects caught by verification

all fixed

Reading the extractor's output against each artifact's source — the actual work of the gate — found six defects. None would have shown up in the benchmark score.

DefectKindEffect

Suffix-less scripts skippedfalse negativeA bundled bin/optimize with no extension was never parsed. Now resolved by shebang.

The two false positives share a root cause worth naming: a string that mentions a path is not a path. The rule is now that a credential literal must be a single whitespace-free token, must not be interpolated, and must not be a docstring.

And three more from code review

Running /code-review before closing found the reachability walk written twice, the enclosing-scope resolver duplicated across two language backends, and — the one that mattered — the taint pass computed and unit-tested but never surfaced anywhere a user could see it. §04 asks for taint; a feature that reaches no output is not delivered. It now appears in both the CLI and the posture channel.

06

Next — P3, where the thesis is decided

P3 is the claim extractor (A5) on a local model with constrained decoding, plus the set algebra and rule table (A6). Its gate is the headline of the whole writeup: FPR on the trap stratum beats every baseline scanner by a wide, defensible margin.

Everything it needs is now in place. B_s is measured and its error rate is known. The posture and risk channels are separated and tested. Taint flows are surfaced and waiting to be promoted. The corpus contains matched pairs — a note-reader and an SSH server touching the same credential path — whose only difference is the claim, which is exactly what A5 has to read correctly.

The risk §11 names for P3 is determinism. Both gates are byte-reproducible today, enforced by test. A model in the pipeline is the first thing that can break that, and if claim extraction drifts between runs the headline number stops meaning anything. Constrained decoding and content-hash caching are load-bearing, not conveniences.
