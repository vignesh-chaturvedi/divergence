01

The hard half was not detection

Anything can flag a near-duplicate. A shadow resembles what it imitates by construction — that is the attack — so similarity alone condemns both, and a shadow detector that also condemns the artifact being attacked is worse than useless.

Similarity alone

github-mcp-server-plus and @modelcontextprotocol/server-github are 72% similar. Which one is the attack? Text cannot say.

Provenance breaks the tie

One is signed with 2.41M downloads/30d, published 2024. The other is unsigned, no download history, published this month. Only the second is flagged.

§04 has A1 record publisher, signature status, first-seen date and download volume. This is what that metadata is for — it never judges an artifact in isolation, it only orders two that already look alike.

When provenance ties, content breaks it

Skills carry no registry metadata at all, so ties are common — the code-review-pro shadow and the real code-review skill are indistinguishable on provenance. The tiebreak: between two near-identical artifacts, the one asserting precedence over the other is the aggressor. A legitimate artifact has no reason to tell the agent to disregard its double. Where neither asserts precedence, the pair is reported as posture rather than condemning a coin flip.

What fleet analysis actually buys

Recall is unchanged, and that is the correct outcome. These artifacts were already caught — under the general name cross_tool_instruction, because from a single artifact that is exactly what shadowing looks like. What P4 adds is attribution: 79.2% → 87.5%. That is precisely what report 04 predicted P4 would buy, and predicting it does not make it a bigger result than it is.

Fleet analysis is registered as a separate scanner rather than folded into the default. Merging it silently would have shown an 8-point attribution lift with no way to say where it came from. As a second row, the contribution is a number the writeup can report.

It holds at corpus scale

Run across all 80 benchmark artifacts rather than the 16-artifact fixture, fleet analysis produces 7 risk findings, every one on a malicious sample, zero false positives. Similarity-based detection over a larger set was the obvious place for precision to collapse, and it did not.

03

Toxic flow is posture, deliberately

The fixture contains three artifacts that are each entirely honest: a web fetcher that says it fetches web pages, a credential store that says it stores credentials, and an HTTP client that says it POSTs anywhere. Together they are untrusted input → private data → egress.

§02 reserves the verdict for divergence between representations. A toxic flow is a capability combination, so it goes to posture — condemning any of those three would be exactly the over-flagging this project exists to eliminate.

It is still worth surfacing, for a reason specific to fleets: no single artifact's documentation can warn about it, because none of them can see the others. That is the clearest statement of why A7 has to exist at all.
