The headline

The strawman does exactly what the April 2026 audit said it would. keyword is a regex scanner built the way the audited tools were built — not a caricature, just the obvious patterns any competent engineer would reach for, with one fateful design choice: every hit reported as risk, no posture channel.

The two false-positive figures answer different questions and both belong in the writeup. FPR-on-traps (57.1%) is the share of trap artifacts wrongly flagged — our headline, because the denominator is a fixed, published corpus anyone can re-run. Share of flags that were wrong (55.0%) is the share of a scanner's own alerts that were false, which is what the audit's 78% measured and what a user actually experiences. They are close here, and reporting only the flattering one would be exactly the sin §06 warns against.

02

Where the strawman breaks

This is the diagnostic the corpus was built to produce. Each trap family isolates one reason a benign artifact looks dangerous, so the failure has an address rather than a percentage.

Trap familyWhat it isolatesWrongly flaggedRate
wildcard_permissionsBenign skills declaring "*" in allowed-tools6 / 7 85.7%
imperative_languageGenuine dependency instructions — "you must call this first"7 / 12 58.3%
broad_but_honest_triggerWide trigger scope that the capability actually matches5 / 9 55.6%
privileged_by_designShell executors, credential managers, browser automation7 / 13 53.8%
security_domain_vocabularySecurity tools that talk about exploits because they scan for them5 / 10 50.0%

The wildcard row is the spec's prediction, confirmed at 85.7%. §03 flagged "*" as the mistake that has already forced a competing benchmark to withdraw headline scores, and predicted that routing it to posture would be worth several points of precision. The strawman routes it to risk and loses six of seven benign skills to it. That single rule is now a measured, defensible claim rather than an assertion.

Structural blind spots

Four attack classes the keyword scanner never detects — not through weak patterns, but because no pattern over text can reach them. These are precisely the cases that need the divergence engine.

Attack classCaughtWhy keywords cannot reach it
annotation_lie0 / 1readOnlyHint: true on a handler that writes. Requires comparing a declared annotation against an extracted capability set — set algebra, not text.
return_value_injection0 / 2Manifest and schema are clean; the payload is in what the handler returns at runtime.
undeclared_filesystem0 / 1The write looks identical to any legitimate write. Only the contradiction with the claim makes it a finding.
bundled_binary_no_source0 / 1The finding is an absence — a binary with no corresponding source. Nothing to match on.

Per §07 this stratum measures what the sandbox adds; it belongs with P5, not P0.

Several samples are built as matched pairs, which is where the corpus earns its keep. A note-reader that reads ~/.ssh/id_rsa while claiming only to read notes is malicious; an SSH server that reads the same path is doing its job. A markdown renderer that promises "entirely offline" and opens a socket is malicious; an HTTP client that promises to fetch any URL is not. The path, the API call and the keyword are identical across each pair. Only the claim-versus-behaviour comparison separates them — which is the thesis, stated as test data.

Every sample carries a written rationale of at least 120 characters, enforced by the validator. §06 is explicit that the rationales are as much of the artifact as the samples, because they are what a reviewer checks when they dispute a verdict. A sample cannot enter the corpus unrationalised.

Safety. All malicious payloads are inert and the validator enforces it: every URL in a positive sample must resolve to a sinkhole (127.0.0.1) or an RFC 2606 reserved domain. Nothing reaches a live host, and the corpus is safe to clone and publish. Negative samples may reference real API hosts, because that realism is exactly what a scanner must learn not to flag.

04

What was built

src/divergence/
├── bench/
│   ├── models.py      Kind · Stratum · Channel · AttackClass · TrapFamily · Finding
│   ├── corpus.py      loader + validator — 11 invariants, all violations at once
│   ├── metrics.py     FPR-on-traps first; per-class recall; per-family FPR
│   ├── report.py      the comparison table + machine-readable JSON
│   └── cli.py         validate · describe · bench
└── adapters/
    ├── base.py        Adapter protocol · registry · crash-isolating runner
    ├── reference.py   null (floor) + keyword (strawman)
    └── external.py    mcp-scan · mcp-shield · semgrep · mcp-scanner — gated
  • Two channels are in the model from the first line. Channel.POSTURE findings are recorded and displayed but never move a verdict. A scanner reporting only posture scores 0% FPR, by construction, and there is a test for it.
  • Attribution is scored separately from detection. A tool that flags a poisoned server for the wrong reason got the right answer by accident; the attrib column tracks that. The strawman scores 72.2%.
  • Undefined never renders as zero. A metric with no denominator prints as —, so an absent baseline can never be mistaken for a perfect one.
  • A crashing scanner does not take down the run. Errors are counted per sample and surfaced in the table — a partial baseline is still a baseline.
  • Unavailable scanners stay visible. They sort to the bottom rather than vanishing, because hiding them would flatter whatever did run.
05

Third-party baselines

awaiting your go-ahead

Four adapters are written and wired: mcp-scan (Invariant Labs), mcp-shield, semgrep, and mcp-scanner (Cisco AI Defense). Each is a real subprocess adapter with a probe command, a scan command and an output parser. None will fetch or execute anything until you set the opt-in.

The parsers — the part most likely to be wrong — are already tested. They are pure functions from stdout to normalised findings, so they are verified against captured fixture payloads (SARIF and flat-JSON shapes) with none of the tools installed. That is what makes deferring the run cheap rather than a hole in the work.

What is still missing without them. The table currently has one real competitor, and it is one I wrote. A strawman I built scoring badly on a corpus I built is a weak claim on its own — §06 is blunt that a benchmark whose author's tool wins every category reads as marketing. The comparison only becomes citable with independent scanners in it. When you want them run:

# downloads and executes third-party scanners locally
DIVERGENCE_ALLOW_EXTERNAL=1 make bench

07

Next — P1, deterministic core

Per §07, P1 is A1 acquisition, A2 declared-interface analyzer, A3 manifest ledger. Zero inference. Its exit gate is a non-zero benchmark score using no model whatsoever.

The corpus already says where those points come from. annotation_lie is a deterministic contradiction between a declared hint and an extracted capability — zero cost, high severity, and the strawman scores 0 on it. The post_approval_mutation samples ship two version snapshots each, waiting for the ledger to diff them. Routing wildcards to posture is a rule, not a model. A1 through A3 should beat the keyword scanner on precision without a single token of inference, and the harness is now in place to prove it rather than claim it.
