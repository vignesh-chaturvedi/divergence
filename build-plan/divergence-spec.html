Divergence

A precision-first analyzer for MCP servers and agent skills. It does not look for dangerous-sounding text. It looks for the gap between what an artifact claims to do and what it actually does — measured statically, then confirmed in a sandbox.

01 — What is actually broken

Scanners are loud and wrong

When an agent connects to an MCP server it receives a manifest — tool names, free-text descriptions, input schemas — and injects all of it straight into the model's context. Those description fields have no length limit, no content validation, no sanitisation. They are executable instructions wearing the costume of documentation. Agent skills work the same way: a description field decides when the skill loads, and bundled scripts do whatever they were written to do.

Three attack families exploit this. Poisoning — adversarial instructions hidden in descriptions or schemas. Shadowing — an artifact mimicking a trusted one, or redefining the agent's behaviour toward a different server entirely. Rug pulls — an artifact that behaves for weeks, then mutates after approval. All three live in natural-language metadata and runtime behaviour. Conventional static analysis sees none of them.

The failure that defines this project

An independent April 2026 audit ran two open-source scanners across 33 servers and 433 tools. Of 27 flagged patterns, only 6 were real — roughly a 78% false positive rate. Eight detections fired on ordinary dependency instructions of the form "You must call this function first." Nine more fired on a browser-automation server for doing browser automation.

That is the whole diagnosis. Pattern matchers cannot separate a legitimate instruction from an adversarial one, because at the level of text they are the same string. And they cannot separate a dangerous capability from a dangerous artifact, because a shell-execution server is supposed to execute shells.

A scanner nobody trusts is a scanner nobody runs. Precision is not a nice-to-have here — it is the entire product.

02 — The idea worth building

Neither surface is decidable alone

There are two surfaces in an agent system. The code surface — source, dependencies, binaries — is what traditional tooling reads. The reasoning surface — descriptions, schemas, capability advertisements — is where these attacks live. Existing scanners pick one and lose.

Read only the code and you miss a poisoned description entirely; the code is clean. Read only the description and you drown in false positives; scary text is usually just honest text. The signal is in neither surface. It is in the disagreement between them.

Core primitive — capability–intent divergence

For every artifact, build independent capability sets and compare them:

  • C — Claim. What the name and description say it does, extracted into a fixed schema.
  • S — Schema. What the input parameters, MCP annotations, or skill frontmatter permit.
  • Bs — Static behaviour. What the implementation reaches for: filesystem, network, environment, subprocess, crypto.
  • Bd — Dynamic behaviour. What it actually touches when executed under observation.

Now the rules write themselves, and they are about relationships rather than substrings:

RelationReadingOutput
B ⊆ CDoes what it advertises, however alarming that isPosture note, not a finding
B ⊄ CReaches for capabilities it never declaredHigh-confidence risk
S ⊄ CAccepts parameters the description never mentionsHidden-interface risk
annot ≠ BreadOnlyHint: true on something that writesCritical — the manifest lies
C ⊄ S ∪ BDescription instructs behaviour the artifact cannot performInjection targeting other tools
Bd ⊄ BsDoes at runtime what its source never showedObfuscation or dynamic loading

The fifth row is the shadowing case, and keyword scanners structurally cannot reach it. An artifact whose description manipulates how the agent treats a different server has no suspicious code and no suspicious capability of its own. It only looks wrong when you notice its instructions exceed its own reach.

The sixth row only became available once the sandbox was in scope, and it is the strongest anti-evasion signal in the system. Static analysis loses to obfuscation; execution does not care how the payload was encoded.

Two output channels, never mixed

Posture describes what an artifact can do — high blast radius, broad filesystem access, wildcard tool permissions. Useful, non-urgent, fires on benign and malicious artifacts alike. Risk describes divergence — a claim the artifact contradicts. Only risk findings count toward the verdict. Splitting these two channels eliminates most of the 78% on its own, before a single model runs.

03 — Why skills were the right scope call

Skills are the thesis in miniature

Adding skills roughly doubles the corpus work. It is worth it anyway, because a skill is the divergence primitive in its purest available form — all three representations sit in one artifact, authored by one person, under no obligation to agree with each other.

SetIn an MCP serverIn an agent skill
CTool description textFrontmatter description
SJSON Schema + annotationsallowed-tools declaration
BsHandler sourceBundled scripts and resources

Two things make skills a distinct problem rather than a copy of the server case, and both produce finding classes with no MCP equivalent.

Description is a routing signal

A skill's description does not merely document it — it decides when the agent loads it at all. A description written to over-trigger is a routing hijack: the skill claims relevance far wider than its actual capability, inserting itself into conversations it has no business in. Detect it as trigger-scope divergence — Ctrigger ⊅ B.

Progressive disclosure hides the payload

The body of a skill file is not loaded until the skill fires, and bundled scripts may never be read by the model at all. A scanner that reads frontmatter and stops sees a clean artifact. The payload is one directory away, and that gap is exactly where a supply-chain attack lives.

The wildcard trap — do not repeat this mistake

A "*" wildcard in a skill's tool permissions looks like an obvious red flag and is not: thousands of entirely benign published artifacts declare it. It is a least-privilege posture issue, not evidence of malice. Existing benchmarks have already had to withdraw headline scores after conflating the two. Route wildcards to the posture channel and keep them out of the verdict — this single rule is worth several points of precision.

Skill-specific finding classes to implement: script capability exceeding allowed-tools; remote resource fetched at load time; credential or environment access unimplied by the description; trigger scope exceeding capability; bundled binary with no corresponding source.

04 — Architecture

Nine components

Ordered by dependency. Each independently testable. The first four contain no model inference at all.

A1

Acquisition

Resolve a target from an npm or PyPI spec, a GitHub URL, a skill directory, a local client config, or a live endpoint. Fetch manifests without executing — static parse of tool-registration calls and skill frontmatter is primary; a sandboxed tools/list is fallback only. Record provenance: publisher, registry record, signature status, first-seen date, typosquat distance to popular names. For skills, walk the full bundle — scripts, resources, anything the frontmatter does not mention.

no inferencetree-sitterregistry APIs
A2

Declared-interface analyzer — S

For servers: parse each tool's JSON Schema; detect undocumented parameters, over-permissive types where an enum belongs, and MCP annotation contradictions. A tool declaring readOnlyHint while its handler writes to disk is a deterministic, zero-cost, high-severity finding. For skills: parse frontmatter, normalise allowed-tools into the same capability vocabulary, and route wildcards to posture.

no inferencedeterministic
A3

Manifest ledger — rug-pull detection

Canonicalise and hash every tool definition and skill bundle at first approval. On rescan, diff and classify: cosmetic (wording), capability-expanding (new params, new sinks, new bundled files), or semantics-inverting (the instruction now says something materially different). Post-approval mutation is the attack MCP's design makes easy and no single-snapshot scanner can catch.

no inferencetemporal
A4

Static behaviour extractor — Bs

tree-sitter parse of the implementation. Walk from each entrypoint — tool handler, or skill script — and collect the reachable capability set: filesystem reads and writes, subprocess spawns, outbound sockets, environment and credential-file access, dynamic evaluation. Then a light taint pass tracking parameters into sinks. Skills need shell grammar alongside TypeScript and Python, and shell is where static analysis is weakest — which is precisely why the sandbox matters.

no inferenceTS · Python · shellreachability
A5

Claim extractor — C

A small local model reads name plus description and emits a fixed capability schema — no prose, constrained decoding, temperature zero, cached by content hash. Output shape: {reads, writes, network, exec, secrets, side_effects, instructs_other_tools, trigger_scope}. Determinism matters more than eloquence; the same description must always produce the same set or the benchmark stops being reproducible.

local modelconstrained decodecached
A6

Divergence engine

Set algebra over C, S, Bs and Bd plus the rule table from §02. Every finding carries concrete evidence — a file:line for the behaviour, the exact description sentence for the claim — and a confidence score. No finding ships without both halves of the contradiction attached. This is what makes output reviewable instead of merely alarming.

no inferenceevidence-bound
A7

Fleet analyzers

Single-artifact scanning is structurally blind to three real attacks, so these operate over the whole installed set. Shadowing: embed all names and descriptions, flag near-duplicates from different publishers. Preference and routing manipulation: score superlative and priority language relative to siblings — "always use this one" is only meaningful against what else is installed. Toxic flow: build a capability graph across servers and skills, flag any path combining untrusted input, private data access, and outbound egress.

local embeddingscross-artifactdifferentiator
A8

Sandbox runner — Bd

Separate Rust crate. Boots a server or executes a skill's scripts under kernel-enforced confinement and records what they actually touch. Normalises the observed trace into the same capability vocabulary as A4, so the divergence engine consumes it without special-casing. Detailed in §05.

Rustseccomp · Landlockoptional dependency
A9

Adjudicator

A frontier model sees only contested cases: mid-confidence findings, and disagreements between representations that the rule table cannot settle. It receives extracted evidence, not the raw artifact, and returns a verdict with reasoning. Hard budget constraint — if more than 5% of findings escalate here, the tiering has failed and the pipeline needs fixing rather than more tokens.

05 — The systems layer

Sandbox runner

Static analysis loses to obfuscation. A base64-encoded payload, a dynamically constructed import, a shell script assembling a command from fragments — all of these defeat reachability analysis and none of them defeat execution under observation. This is the component that makes the scanner hard to evade, and it happens to be the one where Rust is genuinely the right tool rather than a résumé flourish.

Design

  • Filesystem: Landlock LSM restricts the process to an overlay containing decoy credentials — a fake ~/.ssh, a fake token file. Anything that reads them is caught red-handed with no ambiguity to adjudicate.
  • Syscalls: seccomp-bpf in trace mode rather than kill mode. Record everything; block nothing except the genuinely destructive. The goal is observation, not defence.
  • Network: isolated namespace with a recording resolver and a sinkhole. Every attempted egress is logged with its destination, and nothing leaves the host.
  • Normalisation: raw syscall trace collapses into the same capability vocabulary A4 emits, so Bs and Bd are directly comparable.

The payoff is the sixth rule in §02. When Bd ⊄ Bs — the artifact does something at runtime that its source never revealed — that is near-conclusive evidence of deliberate obfuscation. Benign code does not accidentally hide its capabilities from a parser.

Containment rule

The runner ships as its own crate and is an optional dependency. The Python core detects its absence and degrades to static-only with a clear notice. This is deliberate insulation: if the sandbox work overruns — and systems work usually does — it cannot take the rest of the project down with it. The v1 release does not depend on it.

Coverage note: dynamic analysis only observes the paths that actually execute. A tool whose malicious branch requires specific arguments will look clean. Drive it with the benchmark's own inputs and report observed coverage alongside every dynamic finding — the number is part of the result, not a footnote.

06 — The part that gets shared

The corpus

Build the benchmark before the scanner. This inverts the usual order deliberately, and it is the single highest-leverage decision in the plan.

Existing benchmarks in this space measure recall — can a scanner find the planted attack? That is the easy half. Nobody has built a corpus that measures precision against benign artifacts engineered to look malicious, which is exactly where every shipping scanner falls over. The template already exists in application security: the OWASP Benchmark includes safe programs deliberately written to resemble vulnerable ones, formalised in recent work as false-positive traps. No such corpus exists for MCP servers or agent skills.

StratumCountComposition
Malicious~100One or more samples per attack type in the published taxonomy — description poisoning, schema poisoning, return-value injection, shadowing, preference manipulation, post-approval mutation — split across servers and skills, plus hand-authored variants that evade the obvious keyword.
FP traps~150Benign artifacts that look dangerous. Legitimate shell executors. Legitimate credential managers. Genuine dependency instructions phrased imperatively. Browser automation doing browser automation. Database tools running arbitrary SQL by design. Skills with wildcard tool permissions and nothing to hide. This stratum is the contribution.
Benign plain~120Ordinary servers and skills pulled from public registries, sampled across categories for realistic base rates.
Obfuscated~30Malicious payloads deliberately hidden from static analysis. Exists to measure what the sandbox adds over Bs alone — the headline number for the v1.1 writeup.

Every sample carries a written label rationale — why it is malicious, or specifically why it merely looks that way. The rationales are as much of the artifact as the samples, because they are what a reviewer checks when they disagree with your verdict.

Headline metric

Report precision, recall and F1 — but lead with FPR-on-traps, and publish the full table for every open-source scanner you can run alongside yours. "Here is a reproducible corpus, here is how six existing tools score on it, here is where mine wins and where it loses" is a fundamentally stronger artifact than "I built a scanner." It is also the version that gets cited rather than starred and forgotten.

Publish the corpus under a permissive licence with a versioned dataset tag. Report your own losses honestly — a benchmark whose author's tool wins every category reads as marketing and gets dismissed on sight.

07 — Build sequence

Seven phases, one checkpoint

Each phase has an exit gate. Do not start the next until the gate passes. The checkpoint after P4 exists because scope grew on two axes — a shippable artifact must exist before the systems work begins.

P0

Ground truth first

~2 weeks

Build a starter corpus of 80 labelled samples across both artifact types — 25 malicious, 35 traps, 20 benign — before writing any detection code. Write the scoring harness. Run existing open-source scanners against it and record their numbers verbatim.

You now have a metric and a baseline before you have a product. Everything downstream becomes measurable instead of vibes.

Exit gateA single make bench reproduces a baseline comparison table from a clean checkout.
P1

Deterministic core

1–2 weeks

Acquisition (A1), declared-interface analyzer (A2), manifest ledger (A3). Zero inference. Ship a CLI that resolves a server or skill bundle from any supported source, prints its declared surface, flags contradictions, and records a hash for later diffing.

Exit gateNon-zero score on the benchmark using no model whatsoever. Annotation and allowed-tools contradictions alone should already beat something.
P2

Static behaviour extraction

2–3 weeks

tree-sitter grammars for TypeScript, Python and shell. Capability sets from actual API surface. Reachability from handler and script entrypoints, then parameter taint into sinks. Expect this to overrun — it is real static analysis, and shell will fight you.

Exit gateCapability sets manually verified on 50 real artifacts. Track and publish your own false-negative rate.
P3

Divergence engine

1–2 weeks

Claim extractor (A5) on a local model with constrained decoding. Set algebra and the rule table (A6). Split output into posture and risk channels. This is the phase where the thesis either holds or does not.

Exit gateFPR on the trap stratum beats every baseline scanner by a wide, defensible margin. This number is the headline of the writeup.
P4

Fleet and routing analysis

1–2 weeks

Shadowing via embeddings, toxic-flow graph across servers and skills, relative preference and trigger-scope scoring (A7).

Exit gateDetects a planted shadow tool and an over-triggering skill inside a realistic multi-artifact config, without flagging the legitimate originals.

◇ Ship checkpoint — v1

uvx distribution, SARIF output, GitHub Action, benchmark table published, writeup drafted. The project is complete and defensible at this point. Everything after this is upside, and structuring it this way means an overrun in the systems work costs you a version number rather than the whole project.

P5

Sandbox runner

2–3 weeks

Rust crate: Landlock filesystem overlay with decoy credentials, seccomp-bpf trace-mode syscall recording, isolated network namespace with sinkhole, normalisation into the shared capability vocabulary. Wire Bd into the divergence engine as an optional input.

Exit gateCatches at least half the obfuscated stratum that static analysis missed, with observed-coverage reported per finding.
P6

Publish v1.1

~1 week

Final benchmark run across all strata. Writeup covering the divergence thesis, the trap corpus, the static-versus-dynamic delta, and an honest section on where the approach fails.

Exit gateSomeone who is not you runs it against their own config and files an issue.
08 — Stack

Language decisions

Python 3.12 — core

First-class MCP SDK, uvx distribution matching how every tool in this space ships, tree-sitter bindings covering all three target grammars from one codebase, local inference a single import away. Security researchers read Python; that matters for a project whose output is meant to be reviewed.

Rust — sandbox crate

Kernel-level confinement, syscall tracing, namespace isolation. A genuine systems problem where Rust is the correct answer. Shipped separately, consumed over a stable JSON interface, optional at install time.

Explicitly rejected: writing the whole thing in Rust. You would spend the first three weeks on JSON Schema handling and async plumbing instead of the detection logic that is the entire point. Rust earns its place at the sandbox boundary specifically — that is where the systems story is real rather than decorative.

Supporting: tree-sitter for parsing, a local sentence-embedding model for shadowing similarity, a small instruct model for claim extraction, SQLite for the manifest ledger, SARIF for output interchange.

09 — Economics

Cost model

The tiering is a design constraint, not an optimisation. A scanner that costs real money per run does not get adopted, does not get run in CI, and does not survive its own benchmark suite.

TierWorkMarginal cost
T0Acquisition, declared-interface analysis, manifest diffing, provenanceZero
T1Static behaviour extraction, reachability, taintZero
T2Claim extraction, embedding similarity — local modelsCompute only
T2bSandboxed execution — local VM or containerCompute only
T3Adjudication of contested findings — hosted modelCapped at 5% of findings

Cache every model output by content hash. Benchmark runs must be fully reproducible offline after the first pass — otherwise the corpus is not a benchmark, it is a bill.

10 — Boundaries

Non-goals

  • Not a runtime firewall. This analyses artifacts before and between runs. Inline request interception is a different product with different latency constraints.
  • Not a CVE database. Consume existing advisory feeds; do not curate your own.
  • Not multi-language beyond three grammars. TypeScript, Python and shell cover the overwhelming majority of published artifacts. Go and Rust servers are v2 at the earliest.
  • Not a hosted service. Offline-by-default is a feature — the configuration you are asking about is itself sensitive.
  • Not a policy engine. Emit findings; let existing tooling decide what to block.
  • Not cross-platform sandboxing in v1.1. Landlock and seccomp are Linux. macOS and Windows degrade to static-only, stated plainly in the docs.
11 — Honest risks

What could sink this

The space is crowded

Snyk, Cisco, eSentire and several independent projects all ship scanners for this, and a public scanner leaderboard already exists. Detection breadth is not available as a wedge. Precision measurement is — but only if you actually win on it.

Scope grew on two axes

Skills doubled the corpus and the sandbox added a systems subproject. The P4 checkpoint is the mitigation, and it only works if you honour it: ship v1 before touching Rust, even if the sandbox looks more interesting that week.

Labelling is the real work

The trap stratum requires judgement on every sample, and every rationale is something a reviewer can dispute. Slow, unglamorous, and simultaneously the moat — which is exactly why it cannot be deferred.

Static extraction is genuinely hard

Dynamic dispatch, re-exports and wrapper layers defeat naive reachability, and shell defeats nearly everything. Scope aggressively, report your false-negative rate openly, and do not claim soundness you do not have.

Sandbox coverage is partial by nature

Dynamic analysis only sees paths that execute. A malicious branch gated on specific arguments looks clean. Report observed coverage with every dynamic finding or the numbers mislead.

Local model determinism

If claim extraction drifts between runs, the benchmark stops being reproducible and the headline number stops meaning anything. Constrained decoding and content-hash caching are load-bearing, not conveniences.
